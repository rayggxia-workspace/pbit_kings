# 个人任务资料

与任务相关的调研、草稿、图片和辅助文件放在 `work/<github-handle>/<issue-number>/`。例如本仓库存在 Issue #12 且由 `example-user` 处理时，目录可以是 `work/example-user/12/`；这是路径示例，不代表已存在任务或成员。

每个任务资料目录放一个简短 `README.md`：

```markdown
# <任务名称>

- 关联 Issue：<当前仓库的真实 Issue 链接>
- 负责人：<GitHub 用户名>
- 文件说明：<文件名、用途、来源或更新时间>
- 正式成果：<PR 或项目正式目录的链接；未形成则写待完成>
```

这些目录用于整理资料，不是正式代码的统一存放点。项目代码和共同文档按 `docs/ARCHITECTURE.md` 的约定放在正式目录，并通过 PR 审查合并。个人进度写在 `progress/<github-handle>/STATUS.md`，任务状态写在 Issue。

资料应与当前任务有关，文件名要能说明内容。大文件或不适合放进 Git 的原始数据先确认项目约定的存放方式，只提交有权限访问的引用；不要提交密钥、令牌、`.env` 或不应向本仓库成员开放的资料。个人目录不能限制其他仓库成员读取。
